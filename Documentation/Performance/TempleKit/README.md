# 神庙展示区性能检查（2026-09-26）

用户反馈实验场、尤其新导入的神庙附近卡顿。本次针对 `MechanismPlayground` 测试；主地图只进行了对照检查，没有改动地形、水模拟或角色控制。

## 已确认的开销

展示区有 840 个模块、5886 个网格渲染组件（包含各级 LOD）、1961 个静态网格碰撞体。原来虽有三档 LOD，但 PC 的 LOD Bias=2，加上较低的切换阈值，使较远的物体仍然使用高模。重复的建筑构件主要走 SRP Batcher：它降低提交成本，并不自动把所有重复构件变成少数绘制调用。

固定广角机位原来约 3759 次 SRP 绘制调用，加约 13 次普通绘制；总三角面数约 111 万。这是实测可改善的渲染开销。物理模拟在这些测试中约 0.04–0.06 毫秒/帧，不支持“碰撞体太多导致持续低帧率”的判断。当前没有证据证明是远处资源泄漏或未卸载造成；本次没有实现磁盘流式加载/卸载。Unity 的视锥剔除与 LOD 会减少绘制，资源仍可驻留内存。

**验证边界：当前机器没有复现持续严重低帧率。** 固定机位、沿入口跑动的实测多为 4–8 毫秒/帧。不能据此宣称用户所遇到的全部卡顿已经解决，也不能把编辑器偶发长帧都归因于模型。

## 保存的修改

- 120 个模块预制体的 LOD 阈值：`0.35 / 0.10 / 0.005` → `0.70 / 0.32 / 0.005`。近处 LOD0，远处使用组员提供的 LOD1/LOD2；最后一级仍保留较远的显示范围。切换按屏幕相对大小判断，距离还受尺寸、FOV、LOD Bias 影响。
- `Assets/Settings/Rendering/PC_RPAsset.asset`：GPU Resident Drawer → Instanced Drawing。现有 Forward+、SRP Batcher 满足前提，重复网格在 GPU 上实例化提交。
- `ProjectSettings/GraphicsSettings.asset`：BatchRendererGroup Variants → Keep All，避免构建时剥离实例化所需的着色器。代价是相关着色器变体和构建耗时可能增加。
- 增加只在编辑器使用的性能采样菜单。正常运行没有采样或日志开销。

模块仍保持预制体关联，FBX/材质/碰撞/摆放不变。没有关闭远处机关、碰撞或传送门，也没有把整个场景合成不可编辑的大网格。试验过的静态合批和 GPU 遮挡剔除未作为最终配置保留。PC 管线由各场景共享，实例化设置也适用于主地图；Mobile 管线未修改。

参考：[Unity 的 GPU Resident Drawer 配置与前提](https://docs.unity3d.com/cn/6000.0/Manual/urp/gpu-resident-drawer.html)、[SRP 绘制优化方式](https://docs.unity.com/en-us/engine/6000.0/manual/analysis/graphics-performance-profiling/reduce-draw-calls/optimizing-draw-calls-choose-method)。

## 对照结果

Unity 6000.5.9f1，RTX 4060 Laptop，Ryzen 9 7940HX，Game View 1465×1246，PC 画质、LOD Bias=2、VSync=0。实验场未锁帧。每次预热 2 秒，采集 8 秒真实运行帧；不在测量区间内连续调用编辑器工具。时间包括编辑器开销，不代表独立 Windows 构建的最终帧率。GPU 时间来自 FrameTimingManager；绘制统计包含当帧相机及阴影的工作，不能当成场景唯一面数。

| 同一广角机位 `(34,20,-22)`，朝向 `(100,0,30)` | 修改前 | 修改后 |
| --- | ---: | ---: |
| 平均帧间隔 | 5.69 ms | 4.11 ms |
| 帧间隔中位数 | 5.25 ms | 3.94 ms |
| 帧间隔 P95 | 7.32 ms | 5.33 ms |
| CPU 主线程时间（均值） | 3.36 ms | 2.62 ms |
| GPU 时间（均值） | 1.65 ms | 1.19 ms |
| SRP / BRG 主要绘制调用 | 3759 | 439 |
| 普通绘制调用 | 约 13 | 约 13 |
| 总三角面数 | 1,111,831 | 707,583 |

广角平均帧间隔下降约 28%，三角面数下降约 36%，主要绘制调用下降约 88%。仅提前 LOD 时面数降至 807,675，绘制次数仍是 3759，说明单纯低模并不能消除重复提交。

最终使用保存的菜单采样器再测 10 秒，广角平均 4.54 ms、中位数 4.34 ms、P95 5.93 ms，主要绘制调用仍为 439；可见时间会随编辑器状态波动，应把这次结果理解为约 4.1–4.5 ms，而不是保证某个固定 FPS。主地图出生点继续锁 60 FPS，修改后平均 16.84 ms、P95 21.66 ms，修改前为 16.67 / 21.76 ms，未出现持续帧率下降；仍有单次编辑器长帧，未将其算作已解决的问题。记录见 [主地图复测](MainMapAfter.json)。

其他机位没有一致提升：庭院近景 `(64,2,-4)` 平均 4.09 → 4.30 ms；出生点有一个可见传送门时 6.83 → 7.83 ms。后者含额外相机与 GPU 实例化调度，当前仍在约 128 FPS 的量级，但属于应继续观察的代价，不列为性能提升。初次动态采样器使用过逐帧临时数组，旧近景/跑动记录中的 GC 长帧不能单独用于判断游戏 GC；最终采样器预分配存储，采样循环不创建这些临时数组。

## 继续采样与调整

1. 打开实验场，进入 Play，到发生卡顿的位置。
2. 菜单 `Coastal Temple > Diagnostics > Capture performance (10 seconds in Play Mode)`；预热 3 秒后采集 10 秒，可保持机位或按实际路线走动。
3. 结果写到 `Logs/Performance/Manual-日期时间.json`。记录里含机位、分辨率、帧间隔 P95、GPU/CPU 时间和绘制计数。不要在采样期间切场景、编译脚本或运行其他检查。
4. 要调整低模距离，在 `Assets/Prefabs/地形建筑/单件模块` 各分类中的模块根节点修改 LOD Group。增大切换比例会更早降档；不要随意增大末档剔除比例，否则地面构件可能提前消失。
