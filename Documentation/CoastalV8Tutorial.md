# 海岸神庙 V8：教学原型与编辑说明

主场景：[CoastalTemple.unity](../Assets/Scenes/CoastalTemple.unity)。路线从岸边 `(-65,0,204)` 延伸到半山 `(-3,41,121)`，沿用现有山体、庭院和山顶神庙。设计参考为用户提供的[游戏交互设计讨论](https://chatgpt.com/share/6aad66a7-5094-83e9-94fd-f4c45b5e88ec)。本版是可继续编辑、验证的玩法白模。

Windows 试玩：[完整压缩包，约 58.15 MB](../Builds/CoastalTutorial-Windows.zip)。解压全部文件后运行 `CoastalTemple.exe`；同目录的 `开始试玩.txt` 列出操作。直接在本机也可启动 [`CoastalTemple.exe`](../Builds/CoastalTutorial-Windows/CoastalTemple.exe)。本版没有跨次游玩的存档；永久石幕会在当前游玩中保持消失，重新启动会复原实验。

实际画面：[岸边与人物](CoastalV8Verification/06-PlayerAtShore.png)、[水面泳姿](CoastalV8Verification/07-PlayerSwimming.png)、[教学布局全景](CoastalV8Verification/01-TutorialOverview.png)、[投影实验池](CoastalV8Verification/05-WaterMirage.png)。

## 玩家应当学到什么

普通提灯负责照明；驱动机关的是有方向、会被实体遮挡的光束。提灯不会凭空变成解谜激光。取得奖励之前，场景已经提供固定光源，第一段和门户段均不依赖尚未获得的物品供光。

教学先让玩家发现规则，再将已知规则组合使用。刻痕、光束终点、幕帘显隐和台面移动提供证据；铭文与 H 线索供自愿观察，不存在“读过说明才解锁”的条件。通路、碰撞、光照和距离决定能否行动，阶段标题与奖励提示不会替机关设置任务完成计数。

任天堂的开发者访谈强调，用清晰的规则和外观线索支持玩家自行判断，并让玩家尝试自己想到的办法。本原型据此采用一致的对象行为：玩家已经观察到的光照、遮挡和受光反应，应能用于推理后续组合，而不必猜测隐藏任务条件。[任天堂官方访谈，第 5 部分](https://www.nintendo.com/us/whatsnew/ask-the-developer-vol-9-the-legend-of-zelda-tears-of-the-kingdom-part-5/)

奖励包括可反复使用的提灯、永久留下的开口，以及值得停留的半山海湾视野。控制台可以反复尝试，光源方向和门户位置可来回切换；永久石幕的消散则作为已经改变的世界保留。失败不消耗钥匙或尝试次数。

## 三段路线

| 区域 | 规则发现与组合 | 留下的回报 |
| --- | --- | --- |
| `01_FirstLight`：岸边日光 | 初始光照在侧墙；转动导光镜，观察单道斜刻痕的红幕受光变化，再比较移光后的状态。 | 永久开口与可拾取提灯。 |
| `02_BorrowedLight`：共用一束光 | 双条刻痕的入口幕由持续照射保持敞开；进入后，同一光源可以改照单道刻痕的出口幕。让玩家比较“需要持续供光”与“已经留下通路”的差别。 | 持久出口和可停留的观景凹位；入口外的恢复手柄允许回点后重新进入。 |
| `03_FoldedLight`：光从另一端出现 | 固定光束进入成对门户，从移动出口继续传播。出口轨道有停、升、降三个位置，真实出射光是否命中受光器决定升降台动作。 | 乘坐约 3.1 米行程的实体升降台，经落脚台与短坡到达半山视野；上下落脚处均有召回手柄。 |

红色幕帘的两种行为由**单道斜刻痕 / 双条刻痕**区分，不能仅凭颜色判断；青色用于门户。白色与淡黄色用于建筑、道路和人形角色。第三段横向驱动光路位于平台上方，移动光门改变的是实际光路位置，控制台不直接设置“通关”或瞬移台面。

第二段门外的 `Restore_EntranceLight` 操纵原有共用光镜，恢复入口照明，不清除已经消散的永久出口。第三段的 `Recall_Handle` 与 `Upper_Recall_Handle` 都操作同一门户轨道，平台离开后仍可从固定落脚处召回；这些补救操作同样受距离与遮挡限制。

## 可选水中投影实验

`05_Optional_WaterMirage` 是独立水池实验，不是主线门槛。操作台切换灯头向下 **50° / 65° 的俯角**，观察入水前后的光线与墙面落点。光线按斯涅尔定律通过空气—水界面；落点对齐目标时，预先布置的三节投影台阶显现并获得碰撞，移开后解除。

“投影变成可站立台阶”是明确的幻想规则。当前计算范围是一处空气入水界面和一面投影平面，不是体积成像，也不是大气折射率连续变化形成的海市蜃楼。水池保留始终可用的出入楼梯，实验结果不承担唯一逃生路径。

## 操作

| 按键 | 功能 |
| --- | --- |
| WASD / Shift | 移动 / 快走 |
| 空格 / Ctrl | 地面跳跃；水中上浮 / 下潜 |
| E | 操作最近且可达的控制台，或拾取提灯；实体墙会阻挡隔墙操作 |
| C / L | 第一、第三人称切换 / 拾取后开关提灯 |
| H | 可选观察线索；重复按键增加观察细节 |
| Tab / F1、F2、F3 | 切换全景与行走 / 选择观察视点 |
| Home | 返回起点；保留本次游玩中已经发生的机关变化 |

原庭院水池保留现场控制台：靠近后按 E 启动折射排水光源，再按 E 重新蓄水并复原浮台。普通试玩不使用旧水池的 `1 / R` 调试快捷键。全景模式不显示可操作提示，也不能远程触发控制台；角色仍处理重力、浮水和平台跟随，因此在升降台上观察场景时会继续随台移动。游泳自动使用更高的相机锚点与向下俯角，出水后平滑恢复陆地视角。

## 在 Unity 中继续编辑

| 层级根节点 | 编辑内容 |
| --- | --- |
| `10_Geography_EDIT_TERRAIN_HERE` | 原生 Terrain、当前拼接山体与地标；调整地形从这里开始 |
| `20_Architecture` | 岸边落脚点、原庭院与山顶神庙；`04_SummitTemple` 保留现有 `SummitTemple.prefab` 实例连接 |
| `30_Water` | `07_Sea` 近海与远海；原庭院水池仍位于庭院内部，独立实验水池位于教程节点下 |
| `40_Tutorial` | 三段机关、半山观景标记、可选水中投影实验 |
| `50_Player_And_Cameras` | 玩家、相机与观察控制器 |
| `60_Lighting` | 场景太阳光与整体色调 |

直接编辑场景并保存，改动会保留；日常打开或游玩不需要执行生成脚本。地形网格修改后应同步碰撞，并检查路面接缝。水体及其父节点须保持世界零旋转、单位缩放，水域尺寸通过水体参数调整。

教程模板保存在 [`Assets/Prefabs/Tutorial/V8`](../Assets/Prefabs/Tutorial/V8/)：`FirstLight`、`BorrowedLight`、`FoldedLight`，另有 `ExplorerVisual` 与 `WaterMirageSandbox`。三个主线模板是从场景保存的副本；当前场景子树仍可直接编辑，**修改这些模板不会自动同步到当前三段场景对象**。

替换美术时，优先替换视觉子物体，保留功能碰撞、`OpticalCollider`、门户朝向、控制台交互点、升降台 Rigidbody 与已有 Inspector 引用。装饰模型的新碰撞也会挡光；幕帘替换后的渲染器应重新加入 `Visuals`，避免机关消散时只隐藏旧模型。移动控制台、光门或受光器后，应同时检查操作距离、遮挡和完整升降行程。入口恢复手柄须留在可逆幕外，上层召回手柄须留在固定落脚台上，避免跟随平台离开后失去访问途径。

菜单 **Coastal Temple → Author V8 Tutorial** 对应 [`TutorialSceneAuthoring.Build()`](../Assets/Scripts/Editor/Gameplay/TutorialSceneAuthoring.cs)。它是明确的重建操作：会重建 `40_Tutorial`、角色白模及相关网格、材料和模板，覆盖这些对象上的手工调整。仅在确实要按配方重新生成时使用，不能作为每次打开场景或启动游戏的步骤。

V7 原场景保存在 [`Archive/CoastalTemple_V7.unity`](../Assets/Scenes/Archive/CoastalTemple_V7.unity)。归档保留旧场景层级，但共享的 Terrain、网格等资源仍可能被其他场景引用；需要独立修改资源时先另存副本。

试玩后可先问三件事，不提前给出解法：

1. 你依据哪些可见变化判断某个操作有效，而不是猜测游戏要求你做什么？
2. 哪一刻让你觉得得到了值得带走、留下或回看的回报？
3. 后一段用了你先前发现的哪些规则？有没有必须猜测隐藏条件的地方？
