# 沉水庭院 · 水系统第一版

## 试玩

Unity 6000.5.9f1 / URP。打开 `Assets/Scenes/WaterCourtyard.unity` 并 Play。
Windows 试玩包由 `Tools/Build-WaterCourt.ps1` 生成到 `Builds/WaterCourt-Windows/WaterCourt.exe`。
构建输出不提交 Git；源码、场景、预制件、材质和 `.meta` 一起保存在私有仓库。

| 操作 | 功能 |
| --- | --- |
| 1 / 启动排水实验 | 打开固定斜射光源；光在水面折射，照中池底接收器持续 1.5 秒后排水 |
| 右键拖动 / 滚轮 | 观察模式环视 / 缩放 |
| Tab / Esc | 观察模式与第一人称切换；释放或锁定鼠标 |
| WASD / 鼠标 | 第一人称移动 / 看向 |
| Shift / 空格 | 快走 / 跳跃；深水中空格上浮 |
| Ctrl | 深水中下潜 |
| E | 靠近南侧主控台时打开光源 |
| 2 | 在水中施加守恒的局部扰动，观察向周围传播 |

第一次建议先在观察模式按 1，观察水下闸门打开、水位与出流读数、楼梯逐级露出和浮台下降，再按 Tab 沿左侧楼梯走到池底。也可以在满水时进入池中游动，观察水下机关。

## 实际计算了什么

水池 12 × 16 米，最深 4.5 米，初始水面在庭院地面下 0.6 米。池底以 2% 坡度向出口汇水；真实网格碰撞体和数值底部高度使用相同坡度。默认 48 × 64 个水柱单元，每秒 30 次更新，内部按重力波 CFL 条件细分时间步。底部高度图包含实体台阶。

每个单元存储水深，每个相邻面存储带方向的体积流量。重力根据水面高度差驱动流动，阻尼使波动逐渐平息；出流限制器保证单元不会流出超过已有的水量。边界封闭。排水只从指定出口附近单元扣除水量，按孔口水头估算流量，随后周围水流补入。网格顶点高度取自求解结果，湿润区域会退缩；渲染不是仅把平面或 UV 向下移动。

局部扰动把水从一个单元移到邻居，因此不凭空制造水。出流水量累计记录；封闭池和排水池均检查水量账本。出口面积是有效流通面积，适合调节演示速度；它不是管网压力求解器。

### 调节排水快慢

选中水体，在 `WaterVolume` 组件中调节 **Drain Speed Multiplier**；对应 `WaterVolume.cs` 的 `drainSpeedMultiplier`。默认 **4**，范围 0.1–8。此次 Unity 实测从启动光源到排出超过 99.5% 水量约 **45 秒**，包含 1.5 秒接收器充能；设为 **1** 可恢复原来的物理时间。

该参数只加速开闸后的水模拟，保留 CFL 子步与守恒出流，不改 `Time.timeScale`。它是玩法时间加速，角色、重力和浮台物理仍按正常时间运行。倍率越高，求解器 CPU 开销越大。`outletArea` 控制实际出口有效面积，仍可独立调节。最新测试与测量范围见 [海岸场景验证](CoastalTempleVerification/README.md)。

浮力使用四个采样点与刚体受力：按浸没比例计算阿基米德浮力和速度阻尼。浮台冻结横向移动和转动，木块可自由漂浮。重力、楼梯、池底、浮台碰撞由 Unity Physics 处理。角色可随所站浮台移动。

水面使用 URP 场景颜色与深度做近似折射、深度吸收、菲涅耳反射和轻微法线波纹。水下仍保留较高可见度，便于验证机关。光路通过斯涅尔定律独立计算，显示光束与机关判定共用计算结果。排水闸门锁定后不因失光关闭。

## 第一版边界

- 这是重力驱动的高度场 / 虚拟管道近似，适合封闭池、蓄水、排水和漂浮机关。每个水平位置只有一个水面；不支持翻卷浪、独立水滴、瀑布体积、洞穴内叠层水体或完整三维 Navier–Stokes 求解。
- 数值模型以水位与体积可靠为目标，黏性、湍流、涡流和空气夹带没有精确模拟；不能作为工程水力计算工具。
- 固体台阶进入底部高度图；漂浮物是单向浮力耦合，不会实时排开与其体积完全对应的水，也不求解任意移动固体绕流。角色游动施加小幅守恒波动。
- 微小法线波纹是视觉细节，不参与力学；实际的水位和大尺度形变来自数值网格。表面流线来自计算速度，不是预制动画。
- 屏幕空间折射不能显示摄像机画面之外或被遮挡的物体。菲涅耳反射使用简化环境颜色；没有全场景光线追踪和真实焦散。
- 低于 8 毫米的水层不绘制，但仍保留在数值账本中，因此视觉露底不等于数学水量严格归零。
- 本版 R 是实验复位，会瞬间恢复初始水量；没有另做持续注水管道或完整解谜关卡。

## 复用与美术替换

`Assets/WaterSystem/` 是通用水系统，运行程序集 `Courtyard.Water` 不依赖演示场景或 Input System。数值核心 `Runtime/Core/WaterGrid.cs` 不依赖 Unity，可单独跑 .NET 测试。`Assets/WaterCourtyard/` 负责庭院、美术占位、角色、光路机关、界面和验证。

将通用 `WaterVolume` 预制件拖入新场景；设置池域尺寸、底部、初始水位、出口和 `bedBlocks`。仅支持水平轴对齐水域：保持旋转为零、缩放为一，通过尺寸字段调整大小，可平移。尺寸会按单元间距对齐。物理单位为米、秒、千克。场景需要自己的池壁与池底碰撞体。

相机所属 URP 资产必须开启 **Opaque Texture** 和 **Depth Texture**（当前 PC 配置已开启；Mobile 配置没有开启）。水面不使用逐帧 MeshCollider，避免昂贵碰撞体重建。查询水面调用 `Sample`，持续受光调用 `Illuminate`，直接开启排水调用 `OpenDrain`，恢复初始状态调用 `ResetWater`。

给可漂浮物添加 Rigidbody、Collider、BuoyantBody，指定该水域，设置实际排水体尺寸和质量。不要直接缩放物理根节点；改变碰撞体和 `displacementSize`，将美术放在子节点。导轨平台设置 `guided`。

美术成员替换 `Visual — replace with art` 子节点或庭院的渲染体，保留物理根节点、碰撞体、脚本引用和 `.meta`。更换台阶尺寸时同步更新 `bedBlocks`，保证水体和碰撞几何一致。可通过 `Water Court → Rebuild whitebox courtyard` 重新生成实验场景；该命令会覆盖本实验生成场景和资源，完成美术编辑后不要无意运行。

## 验证与构建

```powershell
dotnet restore Tests/Water/WaterChecks.csproj --configfile Tests/Water/NuGet.Config
dotnet run --project Tests/Water/WaterChecks.csproj --configuration Release --no-restore
pwsh -File Tools/Build-WaterCourt.ps1 -UnityEditor 'E:\Unity\6000.5.9f1\Editor\Unity.exe' -Verify
```

独立数值测试覆盖水量守恒、台阶固体、扰动传播、局部排水和水面梯度、闭阀、排空非负、隔墙、时间细分、复位、锁定机关、浸没比例和折射。Windows 验证使用真实渲染与 CharacterController，截图和检查报告输出在试玩包的 `Evidence` 内。验收脚本只在命令行含 `--verify-water` 时运行，正常试玩不自动排水、不自动退出。

性能读数中的“核心”仅包含数值求解，不包含水面网格更新、角色、UI 和 GPU 渲染；FPS 是整个应用的近似表现。验证报告记录测试机器和分辨率，不能当作所有设备的性能承诺。
